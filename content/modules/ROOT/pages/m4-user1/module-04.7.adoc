To provide a end-to-end trusted software pipeline, we rely on a set of tools bundled by Red Hat.
*Red Hat Advanced Developer Suite* is a set of Red Hat products able to build secure pipelines by signing and verifying your build artifacts.
In this part, we focus on Security scanner to detect vulnerabilities (Common Vulneratibilies and Exposures) in the app before running it.
It is what Red Hat Advanced Cluster Security can offer here :

== Red Hat Advanced Cluster Security (ACS) 


Back to the pipeline itself, and let’s look at the 3 Advanced Cluster Security tasks.
The pipeline communicates with Red Hat Advanced Cluster Security with the CLI *roxctl* .

image:m4/rhdh-acs-tasks.png[]

=== Static application security gates

Once the build done, security scans begin .

The bottom-most task is performing CVE scanning via roxctl image scan.

The middle task is performing a policy check via roxctl image check. These policies might be things like 'No log4j allowed' or perhaps no curl, wget, or a package manager in a production image.

The top-most task is to perform YAML scanning via roxctl deployment check, and it might identify that your Deployment.yaml has not properly configured its resource request and limit.

== What makes this app trustworthy ?

image:m4/ingredient-list.jpeg[]


Another important security point is inspecting the application package content know as *Software Bill Of Material*.
Think of the Software Bill of Materials as the ingredient list. I am sure you have gone to the grocery store, picked up an item, and reviewed its packaging. On the back of the product, there will be a list of ingredients. You can find out that something you might wish to eat includes gluten, perhaps too much sugar, or shellfish (my sister is allergic to shellfish), or perhaps nuts. Well, if you are allergic to nuts, you might also be allergic to Struts :-) You might remember that infamous Struts 2 vulnerability that allowed 143 million Americans’ private data to end up on the dark web Struts 2 hack.

In the software development world, packages and dependencies used in an application are extracted as Software Bill Of Material as JSON or XML file.

Currently, the SBOM is stored in the container registry Red Hat Quay and is not in an easily accessible or readable format. Pushing the SBOM to an additional repository allows us to access the raw JSON/XML file for further use outside of the CI process.
